# Сравнение Git и SVN

## 1. Почему ветвление в Git дешёвое?

Ветка Git - небольшая перемещаемая ссылка на коммит; содержимое файлов не копируется, а операция выполняется локально. В SVN ветки представлены каталогами, обычно созданными через svn copy. Копия внутри репозитория тоже может быть дешёвой (copy-on-write), поэтому утверждать, что SVN обязательно физически копирует все файлы, неверно. Однако создание серверной ветки и работа с ней требуют обращения к центральному репозиторию; локальные Git-ветки проще и быстрее использовать для коротких задач.

## 2. Можно ли в SVN сделать коммит без интернета?

Для коммита нужна связь с центральным SVN-сервером. Если сервер доступен в локальной сети или расположен на том же компьютере, интернет не нужен. Без доступа к серверу можно редактировать рабочую копию, но зафиксировать новую серверную ревизию нельзя. Git позволяет создавать локальные коммиты полностью офлайн.

## 3. Когда SVN может быть предпочтительнее?

В существующей инфраструктуре с налаженными SVN-процессами, при необходимости ограничивать доступ к отдельным путям репозитория, при работе с большими бинарными файлами и обязательными блокировками. Решение зависит от требований команды: миграция стабильного проекта только ради смены системы не всегда оправданна.
